## 核对 STM32 固件（learm/Core/Src/main.c）与 action_pkg 的 I2C 协议
- 匹配项：I2C 地址 0x30、32 字节命令/8 字节状态包、小端字节序；ARM('A') 布局 x@4 y@8 z@12 pitch@16 min_pitch@20 max_pitch@24 time uint32@28 一致；SERVO('P') byte4=id / byte8=float 角度一致。
- **不匹配（安全关键）**：固件 `I2C_CommandParse` 的 switch 只有 'A'/'P'(+0xA1)，**没有 'S'(STOP) 分支**；`HostCommandStop()` 存在但主循环从未调用。ROS 发的 STOP('S') 落 default → 回 "BAD_CMD_" 且不置 host_cmd_ready，机械臂不会停。契约 §2.3 规定 STOP byte0='S'、§5.6 要求退出尽力发 STOP。需固件补 'S' case 并接线 HostCommandStop。
- 语义隐患：ROS `_send_end_effector` 把 min_pitch=max_pitch=pitch（fail-safe），固件 `robot_arm_coordinate_set` 是否当 pitch 硬限位待确认（契约 §7 缺口）。
- ROS 侧仅把 8 字节状态当文本发布，未把 "ARM_ERR_"/"NO_SOLVE" 映射成 ArmState.error_code。

## 更正：固件有回状态通道（请求-应答），非单向
- 协议是请求-应答：RDK 写 32 字节命令 → 读 8 字节状态。固件状态码：ARM_OK__/NO_SOLVE/ARM_ERR_/SVO_OK__/STOP_OK_/BAD_CMD_ + 启动码。
- **关键语义**：robot_arm_coordinate_set() 里 theta2servo(kinematics, time) 非阻塞，设完目标即 return true。故 ARM_OK__ = "IK有解+已下发运动"，**不是动作到位**。固件有 robot_arm_knot_is_finish() 能判到位，但 I2C 状态路径未调用 → 固件目前无"完成"状态。
- **真正缺口(非"无回传")**：
  1. RDK poll_status()(10Hz) 只把 8 字节解码成 String 发到 /status_topic，**未映射进 ArmState.state/error_code**。可直接补：NO_SOLVE/ARM_ERR_/BAD_CMD_→STATE_ERROR+error_code；ARM_OK__→至少 MOVING。纯 RDK 侧，不碰硬件。
  2. STATE_SUCCEEDED 无信号源：需(a)固件用 knot_is_finish 汇报到位(改协议) 或 (b)RDK 用 duration_sec 超时推断(估计值)。
  3. sequence_id 关联：建议固件把 seq 回显进状态包，否则 RDK 只能按时间近似对应。
- §4 配置：arm_config.yaml 15 项全齐（i2c_bus/address、command_timeout、min/max_duration、joint_names、servo_id_map、zero_offsets、directions、lower/upper_limits、gripper_closed/open_raw、end_effector_frame/units），无散落常量。✅
- §5 安全：启动静止/单I2C持有/I2C失败转STATE_ERROR/退出发STOP关总线/position_valid不伪造/日志含seq+err_code 均✅；**缺口：过期/重复命令未拒绝**(§5.3)。
- §6 验收：无 pytest 测试、舵机映射/反馈未实机核对、本机无ROS2未构建验证——多为未验证。
- §7 原缺口：ArmCommand/ArmState 已补；单位/舵机映射/急停/通信失败仍待实机确认。
- **固件侧 STOP 缺口(安全)已修复并构建验证**：main.c 改 HOST_CMD_STOP=2 + `case 'S'` + `case HOST_CMD_STOP: HostCommandStop();` + HostCommandStop 循环 `robot_arm_knot_stop(1..6)`（停轨迹/保持位置）。MDK V6.16 构建通过：**0 Error**，仅 ultrasound.c:72 一个既有 VLA warning（与改动无关）。机械臂急停/STOP 现在固件侧真正生效。

## 核对 STM32 库函数可用性（为补 STOP/完成信号做准备）
在 learm/Hiwonder 库里确认以下函数**均存在且可用**（robot_arm.h / robot_arm.c / serial_servo.h/.c）：
- **STOP 修复所需**：`robot_arm_knot_stop(uint8_t id)`(robot_arm.c:280) —— 单关节停止；对串行舵机调 `serial_servo_stop`(发 SERIAL_SERVO_MOVE_STOP=12，停运动但保持力矩/位置)，对PWM舵机则把current_duty重设为当前值(保持)。`serial_servo_load_unload(id, 0)`(serial_servo.h:288) —— 0=掉电/卸力。`action_group_stop()`(robot_arm.c:519) 仅停动作组回放，**不停 coordinate_set 轨迹**，故 STOP 应遍历 robot_arm_knot_stop(1..6)。
  → 结论：补 HostCommandStop 只需在 main.c 循环 robot_arm_knot_stop(1..6)，纯 main.c 改动、不改库。
- **完成信号(SUCCEEDED)**：`robot_arm_knot_is_finish(id, target_duty)`(robot_arm.c:297) 存在（PWM: current_duty==target；串行: 读位置|Δ|<10），`robot_arm_get_knot_current_duty(id)`(robot_arm.c:321) 存在。
  → 不足两点：(a) 目标脉宽在 `theta2servo`(robot_arm.c:16, static) 内部算出且**未全局保存**，main.c 拿不到 target_duty 去轮询 is_finish；(b) 8字节状态包无"完成"状态码，需新增（协议增改）。即完成信号需"库小改(存last target)+main.c加轮询+新增状态字节"，比 STOP 复杂。
- 舵机拓扑：theta2servo 仅驱动 4 个运动学关节(knot[0..3])→串行舵机 6-i 即 id 3/4/5/6；舵机1=夹爪(claw_set)、舵机2=腕旋转(roll_set)。共6舵机=4臂关节+夹爪+腕旋转。

## STATE_SUCCEEDED 完成信号 —— 已补全（固件+ROS2 两侧）
- 采用**准确、单位无关**的完成检测：固件用 `robot_arm_knot_is_finish(id, target)` 读真实位置比对，而非猜时间单位。理由：板子 ARM_SELECT==1→SERVO_TYPE==2（总线舵机），theta2servo 串行路径直接调 serial_servo_set_position；且发现 RDK 把 `int(duration_sec)` 当整数塞进 byte28，与 serial_servo 的 duration 单位不一致 → 若用计时器法会算错，故放弃计时器法改用到位判定。
- **固件改动(robot_arm.c)**：
  - 新增静态跟踪：`g_target_pos[6]`、`g_moving_mask`、`g_motion_active`、`g_motion_start_tick` + `MOTION_DONE_TIMEOUT_MS=30000` 超时保护。
  - 新增函数 `robot_arm_track_target(id,target)` / `robot_arm_clear_motion()` / `robot_arm_motion_active()` / `robot_arm_motion_done()`（在 robot_arm.h 声明）。
  - `theta2servo` case 2 循环里：算 `pos=500+SERIAL_ANGLE_FACTOR*target_angle[i]`，调 serial_servo_set_position 后 `robot_arm_track_target(6-i, pos)` 记录目标。
  - PWM case 1 未跟踪（本板 SERVO_TYPE==2，dead path）。
- **固件改动(main.c)**：
  - `HostServoSet`：serial_servo_set_position 后 `robot_arm_track_target(id, (int)angle)`。
  - `HostCommandStop`：循环 knot_stop 后 `robot_arm_clear_motion()`（急停取消跟踪，避免误报 ARM_DONE）。
  - `while(1)` 主循环：新增 `if (robot_arm_motion_active() && robot_arm_motion_done()) { memcpy(i2c_tx_buf,"ARM_DONE",8); robot_arm_clear_motion(); }`。
  - 新增 8 字节状态字符串 `ARM_DONE`（与既有 ARM_OK__ 等 8-char 约定一致，属协议扩展）。
- **ROS2 改动(arm_controller_node.py)**：
  - 常量 `FW_STATUS_ARM_DONE='ARM_DONE'`；`_decode_firmware_status` 映射 ARM_DONE→(STATE_SUCCEEDED,0,'motion completed')（NO_SOLVE/ARM_ERR_/BAD_CMD_ 保持 ERROR）。
  - `poll_status` 采纳逻辑：STATE_ERROR→_set_error；STATE_SUCCEEDED→**仅当 _state==MOVING 时** _set_state(SUCCEEDED)（防启动期陈旧 ARM_DONE 误报）；其余 MOVING/IDLE→当 _state∈(IDLE,MOVING,SUCCEEDED) 时采纳（让 SUCCEEDED 后下条命令可重新进入 MOVING）。去重与 estop 锁存保护不变。
- **状态机现在完整**：IDLE→(cmd)→MOVING→(ARM_DONE)→SUCCEEDED→(next cmd)→MOVING …；STOP/急停→IDLE/ESTOP；错误→ERROR。
